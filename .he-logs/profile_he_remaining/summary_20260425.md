## Headline

The remaining runtime cliffs split into two distinct families:

1. `pln_roman` + `nars_tuffy` spend most of their time in the generic HE
   `match` pipeline and repeated type/self metadata lookup.
2. `tilepuzzle` spends most of its time in dynamic lookup + term-to-atom /
   dedup machinery from the translated functional queue path.

`hyperpose_primes` is special: the normal SWI profiler mainly sees
`thread_create/3` and autoload setup, which suggests the real work is in worker
threads that need thread-aware profiling rather than plain `profile/1`.

## Per-case read

### tilepuzzle

Key hotspots from `tilepuzzle.profile.txt`:

- `$metta$:bfs_loop_limited/4` has ~91% child time.
- `current_predicate/1` + `clause/2` are hot.
- `he_term_has_state/1` + `he_space_atom/2` are hot.
- `copy_term/2`, `ground/1`, `is_list/1`, `lists:member_/3` are hot.
- `term_to_atom/2` and `janus:py_call/2` show up through `repra`.

Interpretation:

- The translated PeTTa queue/dedup path is paying heavily for generic dynamic
  predicate lookup and generic space scans.
- `add-unique-or-fail` is also paying for `repra`, which pushes work through
  `term_to_atom/2`.

Comparison with CeTTa:

- CeTTa does not use the functional queue here. Its tilepuzzle witnesses use
  `new-space hash`, `new-space queue`, `space-push`, `space-pop`, and
  `space-len`.
- The runtime surfaces are implemented natively in `c-projects/CeTTa/src/eval.c`.

### pln_roman

Key hotspots from `pln_roman.profile.txt`:

- `match/4` dominates child time (~70% inclusive).
- `he_bridge_match_override/4`, `he_bridge_space_ref/2`,
  `he_match_state_semantic/4`, and `he_function_typechain/2` are all hot.
- `nb_getval/2`, `atom_concat/3`, `is_list/1`, `metta_profile/1`,
  `he_term_has_state/1`, and `lists:member_/3` all show up heavily.
- GC cost is also substantial.

Interpretation:

- The slowdown is not in PLN library semantics themselves.
- The runtime is repeatedly paying the generic HE match/type-dispatch cost:
  `match('&self', ...)`, state checks, typechain lookups, and space-ref
  resolution.

Comparison with CeTTa:

- The CeTTa `lib_pln.metta` query surface is still high-level recursive MeTTa.
- The main difference is the runtime underneath it, not a radically different
  query algorithm.

### nars_tuffy

Key hotspots from `nars_tuffy.profile.txt`:

- Almost the same profile shape as `pln_roman`.
- `match/4` again dominates (~72% inclusive).
- `he_bridge_match_override/4`, `he_bridge_space_ref/2`,
  `he_match_state_semantic/4`, and `he_function_typechain/2` all show up.
- `nb_getval/2`, `atom_concat/3`, `is_list/1`, `metta_profile/1`,
  `he_term_has_state/1`, and `lists:member_/3` are again heavy.
- GC cost is again significant.

Interpretation:

- `nars_tuffy` and `pln_roman` appear to share the same runtime bottleneck
  family.
- This looks like a shared HE runtime cost center, not two unrelated library
  issues.

### hyperpose_primes

Key hotspots from `hyperpose_primes.profile.txt`:

- `thread_create/3`
- autoload / library setup

Interpretation:

- Plain `profile/1` is mostly seeing main-thread setup, not the branch work in
  the worker threads created by `hyperpose_runtime`.
- `hyperpose_runtime` currently lowers to:
  `concurrent_and(member(Expr, Exprs), eval(Expr, Out))`
  in `src/translator.pl`.
- This lane needs thread-aware profiling or direct instrumentation around the
  worker path.

## Recommended first specialization tranche

First tranche: **shared HE match/type metadata fast path**

Why this comes first:

- It hits both `pln_roman` and `nars_tuffy`, which share the clearest measured
  hotspot family.
- It attacks a runtime cost that is closer to HE-core execution than the
  extension-heavy tilepuzzle queue/hash surface.
- It is more likely to improve multiple translated examples at once.

Concrete targets:

1. Cache `he_function_typechain/2` / `he_function_typechains/2` instead of
   repeatedly doing `match('&self', [':', Fun, TypeChain], ...)`.
2. Fast-path `he_resolve_space_ref('&self', '&self')`.
3. Reduce generic `match` overhead for common `&self` atom/list patterns that
   do not involve state semantics.
4. Re-check `he_term_has_state/1` on the hot path; it is showing up in all the
   shared-query profiles.

Second tranche after that:

- tilepuzzle/search workloads: move closer to CeTTa’s strategy by adding or
  exploiting native ordered/hash space surfaces for `PeTTa --he` extension
  workloads rather than forcing everything through the functional queue +
  `repra` route.

Third tranche:

- hyperpose: use a thread-aware profiling route and then specialize
  `hyperpose_runtime` if the worker-side evidence agrees.
